# Endless Ocean Generated-Fish Variable Parity Audit

Audit of the legacy `2023-08-16` archive (`data.win`, manifest `9039707068725406600`) against Endless Ocean's chunk-streamed fish spawning and disposal (`src/Jamm.Core/Builtins/EndlessOceanMod.cs` and `src/Jamm.Core/Builtins/Worldgen/*.gml`).

Context: autoplay v2 crashed in Endless Ocean with:
`Variable Dijon.s5(101204, -2147483648) not set before reading it. at gml_Object_SonarPanel_Draw_0`
(evidence: `~/jamm-night/autoplay/apv2b-own-11002/error.txt`, `game.log`, `jamm_autoplay.csv`).

---

## 1. How Endless Ocean creates, updates, and disposes fish

- **Spawning (`gml_Script_jmk_endless_ocean_load`, called from `obj_jmk_endless_ocean` Begin Step / `Step_1` via `jamm_chunk_stream`)**:
  1. Instantiates up to 3 fish per content chunk with `swimmer = instance_create(sx, sy, species);`, which runs the species' `Create` chain (`<Species>_Create_0` -> parent -> `Fish_Create_0`).
  2. Sets `swimmer.jmk_endless_ocean_fish = true`, `swimmer.path_position = layout[i + 3]`, and `swimmer.catalog_index` (via `jamm_catalog_find` or `get_index_for_name(fish_object_to_name(species))`).
- **Lure modifier sync (`src/Jamm.Core/Builtins/Worldgen/step.gml`)**:
  - After `jamm_chunk_stream` loads any new chunks (`loaded_new_chunks`), calls `with (Rod) event_user(0);` (`gml_Object_Rod_Other_10`), which initializes `base_lunge_mod` and updates `base_lunge_offset` on all active `Fish`.
- **Unloading / disposal (`jmk_endless_ocean_release` -> `jmk_endless_ocean_dispose`)**:
  - Reactivates the instance (`instance_activate_object(member)`), preserves it in `ocean_catch` if `state == 4 || state == 15` or hooked by `Lure` (`Lure.fish == id && Lure.hookedFishSize > 0`) or held by `CatSwim` (`CatSwim.holding == id`), otherwise destroys its `light` (if any) and calls `instance_destroy()`.
  - `step.gml` polls `ocean_catch` every Begin Step to dispose fish once vanilla interactions end.
  - `fish_respawn` is prefixed to return `-4` when `jmk_endless_ocean_fish` exists; `SaveManager_Other_14` and `SaveManager_Other_15` skip `[Fishes]` INI writes for `jmk_endless_ocean_fish`.
  - Returning to an unloaded chunk regenerates fresh fish instances from the seed.

## 3. Failure modes by lifecycle situation

1. **First frame after creation (`jmk_endless_ocean_load` in `Begin Step`)**:
   - **Sonar `s1..s5` race (`SonarPanel_Draw_0`)**: If `SonarPanel_Step_1` (`Begin Step`) runs before `obj_jmk_endless_ocean_Step_1` (`Begin Step`), newly created fish never receive `s1..s5` before `SonarPanel_Draw_0` runs in that frame's Draw event. Because GM1.4 pushes function arguments right-to-left in `draw_sprite_ext(s1, s2, x, y, s3, s4, image_angle, color, s5)`, `s5` fails first (`Variable Dijon.s5 not set before reading it.`).
   - **`base_lunge_mod` dependency on `Rod_Other_10`**: `Fish_Create_0` sets `base_lunge_offset = 0` but not `base_lunge_mod`. `step.gml` invokes `with (Rod) event_user(0)` after `jamm_chunk_stream` loads new chunks, which prevents a crash in normal End Step (`PerfMode.Prefix` / `Fish_Other_10`), provided `Rod` exists and the fish is active.
   - **`Torby.mate` at spawn**: If no active `Torby` exists when a chunk spawns a `Torby`, `mate` is `noone` (`-4`) and `Torby_Other_10` crashes on the first Step.
2. **After release / unload / chunk reload (`jmk_endless_ocean_release` / `ocean_catch`)**:
   - **Chunk revisit**: Unloaded non-caught fish are destroyed (`jmk_endless_ocean_dispose`) and recreated on revisit (`jmk_endless_ocean_load`), re-exposing the first-frame `s1..s5` race on every chunk stream-in.
   - **Cross-chunk `Torby.mate` invalidation**: If an EO `Torby` binds `mate` to another EO `Torby` whose chunk unloads first, destroying the mate leaves a dangling `mate` ID in `Torby_Other_10`.
   - **Caught/hooked fish in `ocean_catch`**: `jmk_endless_ocean_dispose` keeps `state == 4`, `state == 15`, `Lure.fish`, and `CatSwim.holding` alive until vanilla ends the interaction, then destroys them on the next `Begin Step`.
3. **Under Perf mode and `FishThinner` deactivation**:
   - **JAMM Perf (`PerfMode.Prefix` in `Fish_Step_2`)**: Only skips `End Step` for distant paused fish (`state == 12` or `state == 0 && !isVisible && lungeCooldown <= 0`); it does **not** call `instance_deactivate_object`, so `SonarPanel_Step_1` and `Rod_Other_10` still update them. Note `PerfMode.Prefix` itself reads `base_lunge_mod`.
   - **Vanilla `FishThinner` (triggered when `fps < 30`, observed in `apv2b-own-11002` at 4–10 fps)**: Deactivates random fish >2000 px from `Lure` with `deactivated = 1; instance_deactivate_object(id);`. Deactivated fish are skipped by `with (Fish)` in `SonarPanel_Step_1` and `Rod_Other_10`. If reactivated later (e.g., by `fish_target_nearest_fish` or `jmk_endless_ocean_dispose` returning `false` on a boat-held fish), `deactivated` stays `1` (so `Fish_Step_2` immediately deactivates it again) and any uninitialized/stale `s1..s5` or `base_lunge_mod` persists until the next `Begin Step`.
