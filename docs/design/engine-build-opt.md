# Engine and build optimisations: Phase 1 measurements and plan

Status: Phase 1 complete; implementation intentionally not started. Measurements and static audits are from the existing local real-file analyses in `docs/reports/decor-sleep.md`, its source profiler captures, and the object/event inspection under `~/jamm-night`. Game archives and extracted game assets remain local and are not part of this report.

## Scope and measurement basis

The target is the legacy GM 1.4 / bytecode 16 `NewWorld` room. The three comparison builds are vanilla, public-five (`pub5`), and all-seven (`all7`). The existing census reports 2,266 / 8,297 / 11,004 placed instances in `NewWorld`, respectively. The dynamic instance counts in a running scene differ because Create and Room Start code spawn objects.

The event rates below combine the room/object census with the existing `--profile` / `--profile-scripts` captures recorded in `docs/reports/decor-sleep.md`. “Cost” is the profiler-attributed time per logic tick, not uninstrumented wall time. The separate benchmark reports in that document provide the unprofiled loop comparison. Capture noise, especially desktop present throttling and OS stalls, makes the median more useful than raw mean for those comparisons.

`Rock_Step_2` is the only high-population truly empty event confirmed by the cited event and object census. Other empty event removals must be archive-specific findings, not assumed from object names. The public-five `Rockbed` handler is a low-call inherited no-op candidate. `MissileSilo_Step_0` appears in the event profile at 1 / 1 / 3 calls per tick, but it is not a safe deletion candidate until inheritance is proven: deleting an empty override can expose a parent event. Breakable rocks, collision objects, and objects read by `instance_exists`, `instance_nearest`, sonar, or save logic are likewise not removable merely because one handler is empty.

### Loop and profiler limits

The unprofiled baseline tables in `docs/reports/decor-sleep.md` show all-seven dock at 53.10 ms mean / 50.93 ms p50 `loop_us` in one controlled pair, and vanilla dock at 19.91 / 19.51 ms. These are whole-loop measurements, not attributable engine-only cost. Existing post-merge `DecorSleep` captures show median loop changes of -12.0% all-seven, -12.2% public-five, and -0.7% vanilla in the dock comparison; these numbers belong to that already implemented pass and are not a forecast for this work.

Subtracting the sum of available non-script profile rows from `loop_us` does not produce a valid engine residual. In the saved vanilla, heavy/public-pack candidate, and all-seven captures, those row totals are approximately 157, 398, and 1,711 ms/tick while `loop_us` is 144, 349, and 1,193 ms/tick. The saved public-pack candidate's original archive hash is not preserved with this worktree, so the exact row is supporting evidence rather than the authoritative `pub5` comparison. Inclusive/nested event wrappers plus instrumentation overhead make the totals exceed loop time. The report therefore does not claim a measured depth-sort or runner-only cost. Before changing depth writes, Phase 2 must add or use non-overlapping exclusive attribution and compare its sum with an unprofiled loop; retain raw runs and repeated controls.

## Decor-to-tile candidate audit

Conversion means replacing eligible room instances with native room tiles in the merged archive. It must preserve room, layer/depth ordering, sprite, source rectangle, scale, blend, alpha, and visibility semantics. A tile cannot carry instance variables, events, identity, collision participation, or be found by instance queries. Static placement alone is insufficient.

| Object/family | Phase 1 disposition | Reason |
| --- | --- | --- |
| `Water1` | **Allowed as the first prototype candidate**, after confirming its exact room placements and tile/sprite geometry in each merged archive | The all-seven audit identifies it as a static object with no Step/Draw logic; its unusually large 10,000 px half-width makes edge/camera and room-boundary parity mandatory. Verify it is not queried or saved by identity. |
| Unparented placed objects with a visible sprite, no effective events, no persistent/controller status, and no inbound instance/collision/save references | **Allowed by rule, candidate list generated per archive at build time** | This is the only safe general class. Report object names and rejection reasons in build diagnostics; fail closed on unknown references, unsupported transforms, or non-room placements. |
| `Rock`, `Rock2..7`, `Rockbed`, `Steel_Stalk`, `Rosebush`, `Blooddrop`, `Astral`, `Sign` | **Not allowed** | Inherits `Collidable`; queried by Lure, Gear, Hookable, and Sonar. Empty `Rock_Step_2` does not make the instance disposable. |

| `SceneItem` and children (`Abyss*`, `Coral*`, `CaveFG*`, `Grass`, `Spike`, `Thorns*`, `TextSign*`, `BGL*`, etc.) | **Not allowed as a family; per-object exception only if it passes the static rule** | Effective Step computes camera parallax; Sonar reads instances; Coral is queried by Fish Create. | `Sea`, `Cliff`, `CliffBottom` | **Not allowed** | `Sea` updates wave/background state and custom Draw handles day/night; the others have special draw/scale semantics. |
| `BreakableRock*`, `Meteor`, `MissileSilo`, `Coral`, `Lilypad`, `WaterCurrent`, `Stream`, `Firefly*`, `Minebomb*`, `Bubble*`, `Hookable` objects | **Not allowed** | Alarms, collision, save/existence checks, RNG, particle behavior, fish interaction, or external object references. |

## Planned passes

All passes must run automatically on every JAMM build and inspect the final merged data, so additions and overrides from every pack are included. A pass must be idempotent and fail closed when an archive is outside the supported GM1 shape. Diagnostics should identify each changed object/event, the measured static count, and any skipped reason.

| Pass | Measured cost / expected gain | Risk | Phase 2 implementation and test plan | Build hook |
| --- | --- | --- | --- | --- |
| Empty event and dead override pruning | Highest proven target: `Rock_Step_2` dispatches 55 / 232 / 472 times per tick; profiler attribution is 15 / 737 / 2,064 µs/tick. Expected gain is removal of those per-instance VM event dispatches; do not extrapolate the profiled µs directly to uninstrumented FPS. `Rockbed_Step_0` is a smaller inherited no-op. | Removing an override can expose parent logic; inherited chains can differ by pack, and mod code can inspect object/event structure. Unreachable-code deletion has weaker evidence and is deferred. | Analyze effective parent event chains after merge. Delete only verified empty handlers, or handlers whose only action is inherited when no ancestor has executable code. Compare room/object/event inventories; run semantic verifier; profile `NewWorld` on all three builds; test mod-added/overridden handlers and descendants; verify behavior with screenshot parity and autoplay. Defer general unreachable-code removal until control-flow proof and independent parity. | New read-only `Jamm.Core` analysis with mutations in the final merged-data optimization stage; run before serialization and semantic verification. Keep a per-event reason/report. |
| Static decor instance to room tile | `Water1` is the first approved analysis candidate; all-seven has many possible object/event dispatches but the number of per-frame savings is not yet measured. Expected benefit: remove instance/event bookkeeping and enable tile batching for proven static art. Quantify in follow-up via eligible/converted tile counts and whole-loop comparison. | Loss of identity, transform, depth, collision, sonar, visibility, save, room streaming, parallax, and special rendering semantics; tile layer can reorder pixels. | Start with `Water1` only. Require no effective events, no hierarchy behavior, no inbound instance references/collision/save dependencies, stable room placement, and representable tile fields. Compare screenshots byte/pixel-wise at dock, sonar, deepwater, and camera edges; autoplay with multiple packs; inspect tile/room diffs; build each pack alone and in all-seven. Add objects only with a per-object allow decision and identical checks. | Post-merge room conversion in `ArchiveBuilder` after asset patches and compatibility repairs, before semantic/reference verification and write. Keep it independent of PerfSettings so every pack receives it. |
| Depth writes / draw-list sorting | A target is hypothesized, not measured. SceneItem has 2,880 Step calls/tick in all-seven but writes `scene_depth = depth + 18` (a variable), then updates parallax x/y; its source does not assign GM `depth` each tick. Earlier Perf depth-transform caching regressed because probes cost more than the transform. Expected gain is currently **unquantified**; optimize only confirmed recurring real `depth` setters. | A guard can change floating-point equality, depth ordering, update timing, inherited behavior, or leave the draw list stale. A GML condition itself may cost more than the engine setter. | First collect exclusive event attribution plus counts of real `depth =` writes and whether values change. Start with a narrow guarded setter only where the assigned value is stable and exact. Compare event state, draw order, screenshot parity, sonar, autoplay, and unprofiled `loop_us` distributions across vanilla/public-five/all-seven. Remove the optimization if the median gain does not exceed repeated baseline variance. | For event code, final merged-data optimizer in `ArchiveBuilder`, after mod conflict selection and before compile/read-back verification. Never duplicate the existing rejected SceneItem transform-cache experiment. |

## Overlap and order of work

* `DecorSleep` already analyzes/sleeps or culls `CaveRock`, `SceneItem`, `Weed`, `Dangler`, lights, and static decor for the optional Perf profile. Do not add another runtime controller, visibility sweep, deactivation path, or duplicate event rewrite for those families. The new universal passes must either share its analysis result or exclude already transformed entries.
* `exp/fish-step-micro` owns generic bytecode optimization. This plan does not add a second dead-code/constant-folding/bytecode optimizer; its event pass is limited to merged object/event dispatch removal and room representation conversion. Coordinate names and generated metadata with that branch before implementation.
* First resolve empty handlers and the exclusive profiler. Then prototype `Water1` tile conversion. Do not begin depth guards until measured setter counts and exclusive cost justify them. Keep pixel-to-bbox masks, light-surface resolution, p99 stutter, and JAMM Lint as later work, outside this phase.

## Acceptance gates for implementation

1. Build from vanilla, public-five, all-seven, and mixed pack orders with the pass automatic and deterministic; never edit input archives.
2. Verify no gameplay or visual changes: same saved/in-memory gameplay behavior, screenshot parity, and `tools/vps/autoplay.sh` for each comparison pack.
3. Report unprofiled `loop_us` mean/p50/p95 with repeated same-build controls, event call counts/times with instrumentation caveats, and a measured exclusive event-vs-runner split. A candidate that does not beat baseline variance is dropped.
4. Confirm no duplicate work with DecorSleep or the parallel fish bytecode optimizer; preserve semantic-reference verification and archive read-back validation.
