How JAMM builds a modded game

A build starts with a read-only legacy archive, resolves selected mods against their common ancestors, applies compatibility rules, and verifies a new game archive.

From original game to a new archive

The legacy August 2023 data.win is the merge ancestor and is opened read-only. A recipe or ModKit source package is compiled locally against that base into a patch; JAMM never downloads a replacement game archive.

Profile order is explicit. JAMM combines each package's added assets and semantic changes, then runs the selected compatibility and runtime installers against the merged result. The output is written to a new path and verified before it can be installed.

How conflict decisions work

Each patch records changes relative to its declared ancestor. Disjoint edits can be combined. Overlapping changes to the same code or resource are reported with the affected asset and require the profile's resolution choice; the selected winner supplies the conflicting hunk while other compatible edits remain.

Identical API placeholders and independent insertions can be retained when their meaning is known. A keep-both decision is limited to compatible code insertions. Area placement resolves follow anchors against the final room, uses the latest selected placement of that same landmark, and reports competing room edits as CGF-AREA-001.

Final compatibility passes include object-index and instance guards such as CGF-INSTANCE-004 (use a typed object constant when checking an object type), CGF-INSTANCE-005 (guard eligible instance member reads/writes), and CGF-INSTANCE-007 (guard eligible lookup-result reads). These are targeted repairs, not a proof that arbitrary dynamic IDs are always valid.

  • Review cgfmm check findings and resolve named conflicts before building.
  • JAMM applies shared Fish, Catalog, Items, Weather and Area runtimes only when the selected package types need them.
  • The verifier compiles and reads back the output archive; the original archive remains untouched.

Anchors and shared APIs

ModKit packages add namespaced assets and initializers instead of replacing shared item tables. During the profile build, JAMM generates deterministic initializer calls in profile load order, replaces API placeholder scripts with the real runtime, and injects the required controller and save hooks.

A recipe can patch known legacy code only when its expected unique anchors are present. If an anchor is missing or ambiguous, the build stops with the entry to inspect rather than silently patching a different location.
